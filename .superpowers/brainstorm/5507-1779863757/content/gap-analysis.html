Gap 1 — Fatal Analysis (Dedicated Page — MISSING ENTIRELY)

What Looker has · What we're missing

NEW

Fatal% as a primary top-level KPI everywhere

Every page shows: CQ Score%, Audit Count, Fatal Count, Fatal%. Fatal% = fatal_count / audit_count × 100. Red color when high. Currently our spec tracks is_critical_call count but never surfaces Fatal% as a standalone KPI with color coding.

→ Add to: CEO Scorecard, T&Q Quality Deep-Dive, PM Overview, Branch Health, Analyst Overview
NEW

"Without Fatal CQ Score%" — separate quality metric

A second quality score that recalculates CQ% excluding all fatal calls. Shows the "true" quality of non-fatal work. In Looker: CQ Score% = 26%, Without Fatal = 36%. Our spec has only one quality score.

→ Add computed field to all quality KPI endpoints: cq_score_excl_fatal
NEW

Top 5 Fatal Contributors — agent-wise fatal leaderboard

Table: Agent Name | Audit Count | Fatal Count | Fatal% (red-coded by severity). Ranked by Fatal%. Completely separate from quality leaderboard. The worst quality agent may not be the worst fatal agent.

→ New endpoint: POST /api/callmaster/tq/fatal-contributors · Add section to T&Q + PM pages
NEW

Day Wise Fatal% trend chart

Bar chart: each day = fatal count + fatal% label. Shows spikes (May 25 had 75% fatal). Our day-wise trends show quality score only, not fatal% separately.

→ Add fatal% line overlay to all day-wise trend charts
NEW

Scenario Wise Fatal Count — Query/Complaint/Request/Sale Done fatal breakdown

4 KPI tiles: Query Fatal (52), Complaint Fatal (18), Request Fatal, Sale Done Fatal (0). Then a day × scenario heatmap table + week × scenario table with fatal%. Fatals broken down by call scenario type.

→ New endpoint: POST /api/callmaster/tq/fatal-by-scenario
Gap 2 — Scenario Dimension (MISSING ENTIRELY)
NEW

Scenario / Sub-Scenario as a first-class filter dimension

Every Looker page has a "Scenario Wise" filter dropdown. Scenarios: Query, Complaint, Request, Sale Done. Sub-scenarios exist under each. This is how inbound calls are categorized by reason. Our entire spec has no concept of Scenario — we only have process (Inbound/Outbound) and call type.

→ Add scenario and sub_scenario filter params to all Inbound endpoints. Add Scenario filter to frontend filter bar for Inbound pages.
NEW

Scenario Wise Count (Detail Analysis)

Query Count (202), Complaint Count (57), Request Count (0), Sale Done Count (1). Top-5 scenario tables with donut charts — one per scenario type. Day × Scenario audit count heatmap. Week × Scenario audit count table.

→ New endpoint: POST /api/callmaster/pm/scenario-breakdown · New section in PM Detail Analysis page
Gap 3 — Detail Analysis Page (MISSING ENTIRELY)
NEW

Agent & Parameter Wise CQ Score% table

Per-agent table showing every parameter score individually: Agent | TQ/MQ/BQ | Audit Count | CQ% | Fatal Count | Fatal% | Opening% | Soft Skills% | Hold Procedure% | Resolution% | Closing%. Color-coded CQ% (red when low). This is the most detailed analyst performance view. Filterable by date range + scenario.

→ New endpoint: POST /api/callmaster/pm/agent-parameter-scorecard · Replace/extend existing analyst-scorecard
NEW

Day Wise Quality Performance table

Date | Audit Count | CQ Score% | Fatal Count | Fatal% | Opening% | Soft Skills% | Hold Procedure% | Resolution% | Closing%. Each row is one day. Filterable by agent + scenario. Shows parameter score movement day by day. Different from our trend charts — this is tabular.

→ New endpoint: POST /api/callmaster/pm/daywise-performance
NEW

Week Wise Quality Performance table

Week 1/2/3/4 | Audit Count | CQ Score% | Fatal Count | Fatal% | Opening% | Soft Skills% | Hold Procedure% | Resolution% | Closing% + Grand Total row. Same as day-wise but rolled up to calendar week of month.

→ Add week grouping to same endpoint with granularity: 'week' param
NEW

TQ/MQ/BQ Agent Classification

Agents tagged as TQ (Top Quality), MQ (Mid Quality), BQ (Bottom Quality) — visible in the agent parameter table. A performance band label per agent. Not the same as quality score band per call.

→ Computed field in agent scorecard endpoint based on avg CQ% thresholds (e.g. TQ ≥ 90%, MQ 80–90%, BQ < 80%)
Gap 4 — Potential Escalation Page (EXISTS IN SPEC BUT FAR TOO THIN)
NEW

Top Negative Signals — 5 distinct sentiment categories

Separate KPI tiles for: Abuse | Threat | Frustration | Slang | Sarcasm. Each is a count with its own trend. Currently our spec lumps all negative signals into "high risk". These are 5 separate AI-detected sentiment categories from the transcript.

→ New endpoint: POST /api/callmaster/tq/negative-signals. New section on Escalation page for all 5 types.
NEW

Social Media & Consumer Court Threat — specific tracking

A dedicated section tracking calls where customer threatened social media escalation or consumer court. Table: CallDate | Founder Names | Social Media | Consumer Court | Total. This is distinct from general risk — it's reputational risk.

→ New field in escalation endpoint: social_media_threat, consumer_court_threat
NEW

Potential Scam — day-wise table

Day × (System Manipulation | Financial Fraud | Collusion | Policy Communication Failure | Total). Heat-mapped by count. Clicking a cell shows the individual lead records. Different from our existing is_critical_call — this is a dedicated scam tracking view.

→ New endpoint: POST /api/callmaster/tq/potential-scam
NEW

Month Wise Negative Signal Trend (stacked bar)

Stacked bar chart by month: Frustration (orange) | Threat (blue) | Slang (green) | Abuse (red). Shows whether negative sentiment is trending up over months. Critical for CEO view too.

→ Add to escalation endpoint response + CEO trend page
NEW

Escalation Detail Panel — full record view

Clicking a flagged lead shows: Call Date | Lead ID | Agent Name | Phone No | Alert type | Sensitive Word Used | Negative Word | Scenario | Sub Scenario | Sensitive word context (AI explanation) | Area for Improvement | Top Negative Signals. Much richer than our current call detail drawer.

→ Extend GET /api/callmaster/pm/call/:id to include: negative_signals, sensitive_word_context, area_for_improvement, alert_type
NEW

Competitor Analysis section

A dedicated section for calls where competitor names were mentioned. Currently no data but the structure exists — month-wise and scenario-wise competitor mention tracking.

→ Add competitor mention flag to escalation endpoint. Can start with empty state, wire when data exists.
Gap 5 — Quality Performance Page Enhancements
NEW

ACHT Categorization — Call Duration Bucketing

Calls bucketed by duration: Average (1–5min), Long (5–10min). Each bucket shows: Audit Count | Score% | Fatal Count | Fatal%. Short calls and long calls perform very differently — this is a required analysis dimension we've completely missed.

→ Need call duration column in db_audit.call_quality_assessment (confirm in schema). New computed field in all Inbound endpoints.
NEW

Parameter Group Scores on main Quality page

Looker shows 5 parameter group scores directly on the Quality Performance page: Opening%, Soft Skills%, Hold Procedure%, Resolution%, Closing%. These are the 5 parameter groups for Inbound (not individual parameters). Our spec shows parameter breakdown only on drilldown.

→ Add parameter group scores to POST /api/callmaster/pm/overview response
ENHANCE

Quality Bands — correct thresholds

Looker uses: 98–100% = Excellent, 90–97% = Good, 85–89% = Average, Below 85% = Below Average. Our spec inherits the SQL view's Hit/Watch/Miss. These need to match Looker's actual bands for Inbound.

→ Update quality_band logic in v_call_master_inbound_kpi view (or compute in service layer)
ENHANCE

Configurable target line per process

Inbound target = 95%. Outbound (Finnable) = 80%. Our spec mentions target lines but doesn't make them configurable per process. Should be stored in ProcessRegistry config.

→ Add qualityTarget field to ProcessRegistry for each process
ENHANCE

Top 5 Performer on Quality page (not just leaderboard page)

Quality Performance page has a "Top 5 Performer" mini-table inline: Agent | Audit Count | CQ% | Fatal Count | Fatal%. Quick-access without navigating to leaderboard.

→ Add top_performers array to PM overview endpoint response
