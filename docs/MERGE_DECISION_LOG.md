| 2026-06-20 | Migration Runner Architecture | Phase-gated migration runner created at `scripts/migrate.ts`. Migrations split into `src/db/migrations/phase1/` (001–011) and `src/db/migrations/phase4/` (012–013). Execution is manual-only via `npm run migrate:phase1` or `npm run migrate:phase4` — never runs on server startup. Separate `scripts/tsconfig.json` with `rootDir: "."` so the runner compiles independently. `scripts/` excluded from root `tsconfig.json` so the main `npm run build` is not polluted. Dotenv loaded via `-r dotenv/config` flag before any module initializer fires. | Phase separation prevents accidental execution of Phase 4 migrations (AI provider config, export audit) during Phase 1 deployment. Manual-only execution enforces operator review and backup gate before any live DB change. Script-scoped tsconfig avoids rootDir conflicts with `src/`. | Runner does not support rollback natively — rollback files are paired SQL files executed manually. No automatic rollback on failure. DDL migrations (CREATE TABLE, ALTER TABLE) cannot be transactionally rolled back in MySQL; operator must repair manually if a statement fails mid-file. |
| 2026-06-20 | Phase 1 Live Migration — dotenv password truncation | `.env` had `DB_PASSWORD` unquoted and the value contained a `#` character. The `#` is a comment delimiter in `.env` syntax; dotenv loaded only the prefix before `#`, causing `Access denied`. Fix: quoted the value in the local `.env` file (never committed). `.env.example` documents that passwords containing `#`, `=`, or spaces must be quoted. **SECURITY NOTE: rotate the DB password — it was exposed in plain text during this implementation session.** | Any future credential with `#`, `=`, or spaces in `.env` must be quoted. This is a local machine file; the fix does not affect other environments unless their `.env` files also have the unquoted value. |
| 2026-06-20 | Phase 1 Live Migration — `ADD COLUMN IF NOT EXISTS` not valid in MySQL 8 | Migration 011 used `ADD COLUMN IF NOT EXISTS` syntax (a MariaDB extension). MySQL 8.0.42 does not support this form. The ALTER failed at statement 1. Migrations 001–010 had already been applied and recorded; 011 was not recorded (runner inserts the row only after all statements succeed). Fix: removed `IF NOT EXISTS` from 011 SQL — safe because pre-migration evidence confirmed both columns were absent. | Future ALTER migrations targeting MySQL 8 must not use `ADD COLUMN IF NOT EXISTS`. Idempotency for ALTER must be achieved via application-level guards (check `SHOW COLUMNS` before running) or by pre-migration evidence confirmation as done here. |
| 2026-06-20 | HEAD.lock Environment Risk | VS Code's git extension holds `.git/HEAD.lock` persistently on this machine, preventing normal `git commit`, `git checkout`, and `git branch -m` operations. Workaround: use `git commit-tree` + direct ref file writes. | Workaround used only when repository state was verified clean via `git fsck --no-reflogs` and `git log`. Every future task must run `git status --short` before and after any commit attempt. Direct ref writes are safe only when both branch and HEAD are at identical known-good commits. | If HEAD.lock workaround is used on a dirty or diverged working tree, it can silently corrupt the branch. Every task must verify `git rev-parse HEAD` matches expected SHA after each commit-tree operation. |
